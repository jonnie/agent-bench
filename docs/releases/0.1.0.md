# Agent Bench v0.1.0 — experimental alpha

The first versioned release of Agent Bench: a host-side CLI for comparing **one LAN-hosted LLM** across **pi**, **oh-my-pi**, and **OpenCode**, using fresh Docker containers and independent grading.

## Included

- Five synthetic Python tasks: bug fixing, a small feature, system refactoring, security hardening, and performance optimization.
- Extensible individual task modules and `default`, `core`, and `robustness` task sets. A run can select multiple sets and individual tasks without duplicate execution.
- Repeat scheduling, resource/time/output limits, correctness and success metrics, timing, usage coverage, patch diagnostics, and per-task/per-set comparisons.
- One JSON report and one standalone, offline HTML report per run. Schema-version-1 JSON supports website tables/charts and results-backed articles.
- Docker images for all three harnesses, llama.cpp API/thinking controls, and Linux workspace ownership handling.
- Linux/macOS unit checks, package installation checks, and Docker integration tests against a local mock model API.
- Contributor/security guidance and a reviewed historical 45-attempt example that preserves failures.

## Installation

Requires **Python 3.11+** and **Docker Desktop or Docker Engine**. The framework does not serve model weights; configure a separate OpenAI-compatible model endpoint, such as llama.cpp, with tool calling enabled.

Install from the release tag in a virtual environment:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install 'git+https://github.com/jonnie/agent-bench.git@v0.1.0'
.venv/bin/agent-bench list
.venv/bin/agent-bench build
```

Alternatively, download the attached wheel and install it using pip. The source archive includes contributor documentation, tests, and the reviewed example. The Python CLI has no runtime package dependencies. Container builds download upstream tools and dependencies.

**This release is not published to PyPI.** Do not use an unverified `pip install agent-bench` distribution.

See the [README at v0.1.0](https://github.com/jonnie/agent-bench/blob/v0.1.0/README.md) for run commands, model configuration, and metric definitions.

## Limitations and responsible interpretation

- This is **experimental alpha software**, not a comprehensive coding leaderboard. The five small synthetic Python tasks measure this suite, not universal model coding ability.
- Results evaluate **model + harness**. Native prompts, tools, policies, and auxiliary calls differ across harnesses. Missing usage data remains unknown, not zero.
- Record model weights, quantization, llama.cpp build, server hardware/settings, framework commit, task/test hashes, and image identities. Timings are not directly comparable across different hardware, architectures, or emulation settings.
- Direct harness versions are pinned, but base image tags and some transitive dependencies can change. Retain the actual images and report metadata for reproducibility.
- Docker is **not a complete sandbox for hostile generated code**. Use disposable/dedicated environments, restrict network access, and review the [security policy](https://github.com/jonnie/agent-bench/blob/v0.1.0/SECURITY.md).
- Raw reports can contain sensitive endpoints, paths, prompts, tool output, and transcripts. Review and sanitize publication copies; preserve failures and never invent missing measurements.
- The published example is a sanitized historical run with incomplete model/server provenance, not an exact reproduction recipe or a claim about all deployments of that model.

Future releases may change CLI or task contracts. Changes affecting grading or result comparability will be called out in the changelog. Framework versions and report schema versions are separate contracts.
